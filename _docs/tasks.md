# Agent Activity Dashboard — MVP Backlog

技术栈已选择方案 A：TypeScript、React、Vite、Fastify、SQLite；数据库访问优先使用 better-sqlite3，测试使用 Vitest，浏览器验收使用 Playwright，SSH 调用系统 OpenSSH。

需求依据为 `_docs/plan.md`；本文件仅拆分工作，不改变已冻结的 MVP 范围。每个编号是一项可单独交接、以一次工作会话为目标的任务，描述中包含所需输入、工作边界和验收方式；有前置依赖的任务可以独立交接，但不代表可以任意顺序实施。

建议代码边界为 `apps/server`、`apps/web` 和 `packages/contracts`，测试夹具放在 `tests/fixtures`，采集研究结论放在 `_docs/research`。这些路径是后续任务的交付约定，本次只创建 backlog，不搭建工程或编写代码。

PoC 必须记录实际验证的操作系统、工具版本、数据来源和能力限制，只保存脱敏夹具。无法取得代表性安装、远端访问或可靠证据时，交付复现步骤和阻塞说明，不编造验证结果；任务 15 的可行性门槛通过前，不开始任务 34–39 的 UI 开发。

## 1. 搭建 TypeScript 工程并通过首个测试
Goal: 建立可以安装、构建和测试的最小后端工程。
Description: 初始化 npm workspace、TypeScript 严格模式、Fastify 和 Vitest，建立 `apps/server` 与 `packages/contracts`，在开发说明中预留 React/Vite 前端目录而不实现 UI。提供最小健康检查接口和使用 Fastify inject 验证真实响应的测试，避免仅添加恒真断言。验收要求从干净依赖安装开始，根目录的测试、类型检查和构建命令全部通过，并记录启动命令。

## 2. 定义采集证据与会话数据契约
Goal: 为来源适配器、状态计算和 API 建立统一的类型边界。
Description: 在任务 1 的共享包中定义来源类型、原生会话命名空间、记录存储主机、工作目录所属主机、最新任务标识、事件时间、采集时间、证据和能力声明，明确 Running、Waiting、Unread、Read、Unknown 与独立的新鲜度字段。为用户指令、最终响应、时长和 Git 信息定义缺失值语义及运行时校验，不用空字符串或推测值冒充已知数据。通过契约测试验证无效输入被拒绝、未知来源事件可安全保留为诊断信息，产出简短的字段说明。

## 3. 实现本地只读采集访问层
Goal: 让适配器通过统一接口读取本地文件和查询进程信息。
Description: 基于任务 2 的契约提供受限文件枚举、范围读取、元数据查询和带超时的进程查询接口，支持当前 Windows 工作站并显式报告尚未支持的平台操作。处理权限不足、文件消失、路径空格、中文路径及读取中追加的文件，不根据进程是否存在直接计算任务状态。使用临时目录和可替换的命令执行器验证只读行为、错误分类与取消机制。

## 4. 导入 SSH 配置并解析目标主机
Goal: 从现有 SSH 配置提取可选择的主机并复用有效连接参数。
Description: 基于任务 1 的后端工程读取本机 SSH 配置，处理明确的 Host 别名和 Include，保留通配规则的语义而不把通配表达式展开成虚构主机。对选定目标调用系统 `ssh -G` 解析有效配置，使 SSH 自己处理连接选项，并说明 Match 或动态规则造成的枚举限制。使用配置夹具验证包含文件、别名、重复项、缺失文件和 ProxyJump，确保不复制私钥或保存密码。

## 5. 实现有超时的 SSH 只读执行层
Goal: 在不安装远端采集器的前提下执行可控的远端读取。
Description: 使用任务 4 的主机解析结果和任务 2 的错误契约，通过系统 OpenSSH 执行已定义的只读操作，设置连接与执行超时、非交互认证和输出大小限制。明确本地参数传递与远端 shell 转义的边界，探测远端系统和已有命令能力，不假定安装了 Python、Node 或 sqlite3。验证带空格及特殊字符的路径、认证失败、未知主机密钥、超时和取消，并记录失败原因而不关闭主机密钥校验。

## 6. 验证 Codex CLI 会话发现与详情提取
Goal: 确认 Codex CLI 的真实记录位置、稳定身份和最新任务字段。
Description: 使用任务 3 和任务 5 的只读访问层检查代表性的本地与 SSH 远端 Codex CLI 安装，验证会话发现、原生会话 ID、工作目录、最新用户指令和最终响应的实际来源。将字段位置、版本差异、重复发现规则及可获取的时间信息写入 `_docs/research/codex-cli.md`，保存最小脱敏样本。通过样本回放证明多轮会话仍只有一个稳定会话身份，无法验证的环境明确列为限制。

## 7. 验证 Codex CLI 生命周期证据
Goal: 建立有真实样本支持的 Codex CLI 状态能力表。
Description: 以任务 6 的发现方法为输入，收集新任务开始、持续执行、明确完成、等待审批或输入、恢复执行、异常退出和原生查看的代表性证据。扩充 `_docs/research/codex-cli.md`，分别声明每种状态或查看信号是否可靠，空闲进程不能证明 Running，退出不能证明完成。用脱敏事件序列验证预期判定，缺失终止证据或冲突信号必须得到 Unknown，无法识别原生已读时记录 Web-only 回退。

## 8. 验证 Cursor CLI 会话发现与详情提取
Goal: 确认 cursor-agent 的真实记录位置、稳定身份和最新任务字段。
Description: 使用任务 3 和任务 5 的只读访问层检查代表性的本地与 SSH 远端 Cursor CLI 安装，验证会话枚举、原生 ID、工作目录、最新用户指令、最终响应和时间字段。将记录格式、可访问条件及与 Cursor IDE 数据的关系写入 `_docs/research/cursor-cli.md`，保存最小脱敏样本。通过样本回放验证多轮合并和来源命名空间，不能因为工具名称相似就套用 IDE 或 Codex 的解析规则。

## 9. 验证 Cursor CLI 生命周期证据
Goal: 建立有真实样本支持的 Cursor CLI 状态能力表。
Description: 以任务 8 的发现方法为输入，验证新任务、执行进展、明确完成、等待、恢复、异常退出和原生查看信号，并记录适用版本。把支持范围和降级规则补充到 `_docs/research/cursor-cli.md`，等待与已读能力不得从其他来源的能力推导。使用脱敏事件序列验证可靠事件与缺失事件的区别，进程消失但无完成事件时判为 Unknown。

## 10. 验证 Cursor IDE 会话存储与一致性读取
Goal: 找到 Cursor IDE Agent/Composer 会话并验证运行中数据的只读访问方式。
Description: 使用任务 3 的访问层检查代表性 Cursor IDE 安装，验证原生会话身份、最新指令、最终响应、工作目录及记录存储位置，并写入 `_docs/research/cursor-ide.md`。如果来源使用 SQLite，验证运行中数据库、WAL 和文件锁条件下的一致性读取方案，不把直接复制单个数据库文件当作可靠快照，也不修改来源数据库设置。保存脱敏夹具并记录读取失败及版本差异，使用正在写入的测试数据库或等价代表样本验证读取不会生成伪完整记录。

## 11. 验证 Cursor IDE 生命周期证据
Goal: 确定 Cursor IDE 哪些任务状态和原生查看行为可以可靠识别。
Description: 基于任务 10 的读取方法验证任务开始、执行、完成、等待审批或输入、恢复、IDE 异常关闭和查看会话的可观察信号。将证据、信号延迟和支持范围补充到 `_docs/research/cursor-ide.md`，明确执行活动与普通界面操作的区别。以脱敏样本验证每项宣称支持的行为，无法识别的状态降级为 Unknown，原生已读不可靠时采用 Web-only。

## 12. 验证 Cursor IDE Remote-SSH 会话归属
Goal: 正确区分 IDE 记录存储位置与远端项目实际位置。
Description: 使用任务 5 和任务 10 的能力检查一个代表性 Cursor Remote-SSH 工作区，确认会话记录位于本地还是远端，并提取工作区主机、远端目录和可用 Git 线索。把映射方法写入 `_docs/research/cursor-remote-ssh.md`，区分原生会话来源命名空间与工作目录主机，记录重复发现时如何避免生成两张卡片。验证不同远端上的同名路径、重连和无法解析的远端身份，证据不足时保留歧义而不猜测归属。

## 13. 验证 Git 仓库与 worktree 身份算法
Goal: 形成可验证的跨主机项目分组规则。
Description: 使用任务 3 和任务 5 的读取能力，在普通仓库、多个 worktree、SSH/HTTPS origin、无 remote 仓库和非 Git 目录上验证 Git 元数据解析。将共同仓库定位、远端地址规范化、主机命名空间和歧义回退规则写入 `_docs/research/project-identity.md`，只合并有可靠证据的同一仓库。用成对样本验证应合并与不应合并的情况，覆盖同名目录、不同仓库路径以及 worktree 的分支信息。

## 14. 验证 SSH 轮询成本与远端读取限制
Goal: 判断现有只读采集方式能否支撑每 15 秒扫描。
Description: 使用任务 5 和三个来源的 PoC，在已配置的代表性主机上测量发现、增量读取和必要元数据查询的耗时与传输量，记录测试主机、数据规模和可用工具。特别验证大日志、慢连接以及远端运行中 SQLite 的一致性读取条件，不以安装远端依赖或复制不一致数据库规避限制。将结果和可复现命令写入 `_docs/research/polling.md`，给出超时、并发、增量游标和不支持环境的建议，不在该任务实现正式调度器。

## 15. 汇总采集可行性并冻结适配器契约
Goal: 在开发 UI 前明确三个来源经过验证的支持范围。
Description: 汇总任务 6–14 的研究产物，在 `_docs/research/feasibility.md` 中列出来源、版本、平台、发现能力、状态证据、原生已读、Remote-SSH 归属和性能限制，并更新任务 2 的契约以表达实际发现。对每个宣称支持的能力关联真实证据和回放夹具，验证不支持的能力可以按 `_docs/plan.md` 降级而不伪造状态。明确写出通过或阻塞结论，缺少代表性验证或无法安全读取关键来源时保持门槛未通过并列出最小补充验证项。

## 16. 建立 SQLite 存储与迁移
Goal: 持久化应用配置、会话快照、证据、已读标记和扫描进度。
Description: 基于任务 15 确认的数据契约，使用 better-sqlite3 建立应用自己的数据库及版本化迁移，包含稳定主机和会话身份、最新任务、时间字段、来源能力与增量游标。提供事务边界和明确的数据目录，避免把应用数据库与 Agent 来源数据库混用，不保存完整历史会话或 SSH 凭据。使用临时数据库验证首次初始化、重复启动、迁移失败处理及关闭后重开时数据保持一致。

## 17. 实现监控主机配置仓储
Goal: 持久保存用户选择的监控目标并始终自动监控本机。
Description: 基于任务 16 的存储和任务 4 的 SSH 候选主机，提供添加、移除、启用、停用与查询监控目标的仓储接口，将应用设置与原有 SSH 配置分开。为主机保存稳定身份，移除后不再调度且从活动看板排除，重新选择同一目标时避免生成重复会话身份。验证服务重启、重复添加、本机不可被误移除以及配置中不包含密码或私钥内容。

## 18. 实现基于证据的任务状态归约器
Goal: 将规范化执行事件确定性地归约为最新任务状态。
Description: 基于任务 15 的契约实现与 IO 无关的状态归约器，处理 Running、Waiting、明确完成与 Unknown，新一轮任务替换旧任务而不新增会话卡片。保留证据原因和任务标识，处理重复、乱序、不完整及冲突事件，进程存在或退出都不能单独证明执行或完成。通过表驱动测试覆盖等待恢复、完成后再开始、异常退出和旧任务事件迟到，确保旧事件不会覆盖新任务。

## 19. 实现首次导入与 Web 已读语义
Goal: 正确区分历史完成任务、新完成任务与已查看任务。
Description: 基于任务 16 的持久化和任务 18 的任务身份，保存每个来源的首次成功导入边界，使历史已完成任务初始化为 Read，历史运行中的任务完成后变为 Unread。实现按最新任务标识记录的 Web 已读操作，新任务开始时清除上一任务的已读效果，重启不得把既有 Unread 重置为历史 Read。用可控时间测试首次导入期间完成、失败后重试、离线后恢复，以及用户打开旧任务时新任务恰好开始的竞态。

## 20. 接入可靠的原生查看证据
Goal: 仅在来源证据可靠时同步最新已完成任务的原生已读状态。
Description: 基于任务 15 的来源能力表和任务 19 的已读仓储，接入已经验证的原生查看事件，并要求事件能关联到正确的会话和最新任务。对于没有可靠信号的来源保持 Web-only，不把进程存在、窗口聚焦或记录文件访问时间当成查看证据。验证迟到的旧任务查看事件不会读掉新任务，若所有来源均不支持则交付明确的禁用能力声明和对应回退测试。

## 21. 实现 Codex CLI 正式适配器
Goal: 将已验证的 Codex CLI 记录转换成统一的会话与任务证据。
Description: 使用 `_docs/research/codex-cli.md`、任务 15 的契约以及任务 3/5 的访问接口实现可复用适配器，支持已验证的本地与远端记录格式。提取最新任务指令、最终响应、目录和时间，输出能力限制与解析错误，不在适配器内部重复实现全局已读或项目分组逻辑。使用 PoC 脱敏夹具验证正常、等待、完成、截断、未知事件和不支持版本的输出。

## 22. 实现 Cursor CLI 正式适配器
Goal: 将已验证的 cursor-agent 记录转换成统一的会话与任务证据。
Description: 使用 `_docs/research/cursor-cli.md`、任务 15 的契约以及任务 3/5 的访问接口实现 Cursor CLI 适配器，遵守已经验证的来源身份和记录位置规则。输出最新任务详情、执行证据和字段不可用原因，避免把 CLI 与 IDE 的记录无依据地重复或合并。通过 PoC 脱敏夹具验证多轮、异常中断、等待能力缺失和未知版本时的行为。

## 23. 实现 Cursor IDE 正式适配器
Goal: 安全读取已验证的 IDE 会话并保留 Remote-SSH 工作区归属。
Description: 使用 `_docs/research/cursor-ide.md`、`_docs/research/cursor-remote-ssh.md` 和任务 15 的契约实现 IDE 适配器，采用已验证的一致性读取方式。区分记录存储主机与工作目录主机，输出最新任务详情、能力限制和归属歧义，避免在本地与远端扫描中重复生成会话。通过脱敏夹具验证本地工作区、Remote-SSH、数据库忙、读取不完整和无法解析远端身份的情况。

## 24. 实现项目身份解析器
Goal: 将会话归入可靠的逻辑仓库或带主机命名空间的目录项目。
Description: 按 `_docs/research/project-identity.md` 的已验证规则，使用本地或 SSH 访问接口解析 Git common directory、origin、分支和 worktree，输出稳定项目键及展示信息。只有明确相同的仓库才跨主机合并，无 remote 或身份不明时采用稳定回退键，非 Git 目录始终包含工作目录所属主机。使用成对仓库夹具验证 worktree 合并、SSH/HTTPS 规范化、不相关目录隔离和 Git 元数据不可读时的回退。

## 25. 实现增量读取与来源检查点
Goal: 避免每轮扫描重新传输和解析所有历史记录。
Description: 基于任务 16 的游标存储和任务 21–23 的适配器接口，按来源支持程度记录文件身份、偏移或可靠的记录版本，提供增量读取结果及待提交检查点。处理日志截断、轮转、半行写入、重复记录和非追加式存储，不能仅用修改时间判断 Agent 执行活动，不能因文件未变而跳过必要的存活证据检查。通过夹具验证恢复后不遗漏终止事件，并保证检查点只在对应会话更新成功持久化后推进。

## 26. 串联单次采集与原子持久化
Goal: 完成从一次来源扫描到可查询会话快照的完整后端流程。
Description: 组合任务 18–25 的适配器、归约器、已读规则、项目解析和检查点，对指定主机执行一次扫描，并在事务中提交最新任务快照和对应检查点。区分来源未安装、权限错误、部分解析失败和成功空结果，单个来源失败不得抹掉其他来源的结果或已有会话缓存。通过注入失败的集成测试验证重试幂等、事务回滚、重复发现去重和失败后检查点不提前推进。

## 27. 实现 15 秒后台调度与手动触发入口
Goal: 在浏览器关闭时持续扫描，并保证同一目标不会重叠执行。
Description: 基于任务 17 的监控配置与任务 26 的单次扫描服务，实现启动扫描、每 15 秒调度、每主机执行锁、有限并发和可取消的关闭流程。手动触发复用相同入口，对仍在运行的目标合并或跳过请求并返回明确结果，一台慢主机不能阻塞其他主机提交结果。使用虚拟时钟和可控扫描器验证节拍、超时、同目标防重入、停用主机和服务关闭。

## 28. 实现主机连接状态与数据新鲜度
Goal: 保留离线缓存，同时明确区分当前证据与过期状态。
Description: 基于任务 26/27 的扫描结果保存最近尝试、最近成功、错误原因和当前扫描状态，分别表达主机连接失败、来源读取失败及长时间未更新。保留最后一次会话快照和已知任务状态，但对离线或过期来源附加可查询的新鲜度标记，不把缓存 Running 计为已验证的当前运行。验证断线、部分来源失败、重启后尚未扫描和恢复连接，恢复时按新证据更新而不伪造完成事件。

## 29. 实现看板过滤、排序与计数查询
Goal: 按产品规则返回项目优先的可见会话集合。
Description: 基于任务 16 的存储和任务 28 的新鲜度，按真实 Agent 活动时间计算项目滚动 7 天可见性，只隐藏最新任务完成超过 24 小时的 Read 会话。项目按最新 Agent 活动降序，已知状态按 Waiting、Unread、Running、Read 排序且组内按活动时间降序，Unknown 单独返回供 UI 明确展示，计数区分当前与过期数据。使用固定时钟验证时间边界、Unread 保留、查看不刷新项目活动、项目超出 7 天，以及 Read 被隐藏后项目仍在活动窗口内的情况。

## 30. 提供项目列表与会话详情 API
Goal: 为看板提供稳定、经过校验的只读数据接口。
Description: 基于任务 29 的查询和任务 2/15 的共享契约，在 Fastify 中实现项目列表与单会话最新任务详情接口，返回来源、主机、目录、Git 信息、时间、证据原因和新鲜度。详情只包含最新用户指令与最终响应，字段缺失明确表达为不可用，接口读取本身不修改已读状态，也不触发完整历史扫描。使用 Fastify inject 验证响应契约、空数据、未知会话、离线缓存和部分字段缺失。

## 31. 提供按任务标识确认已读的 API
Goal: 让详情视图安全地将所打开的已完成任务标为 Read。
Description: 基于任务 19 的仓储实现幂等已读接口，请求包含会话身份及打开时的任务标识，只允许标记匹配的已完成任务。任务已更换时返回明确的冲突或未应用结果，不把用户查看旧内容的动作应用到新任务，并让响应足以更新前端计数。通过接口测试验证重复请求、运行中任务、旧任务竞态和数据库重开后标记仍然存在。

## 32. 提供 SSH 候选与监控主机设置 API
Goal: 允许 Web 设置页面管理监控目标并查看扫描问题。
Description: 基于任务 4 的候选导入、任务 17 的仓储和任务 28 的扫描状态，实现候选列表、当前目标列表、添加、移除与启停接口。支持选择已有 SSH 别名或添加明确目标，校验输入并复用系统连接配置，不写入用户原始 SSH 配置，不接收或保存私钥与密码。通过接口测试验证重复目标、无效输入、本机保护、持久化和失败原因展示所需字段。

## 33. 提供非阻塞手动刷新 API
Goal: 让用户触发刷新并获得可跟踪的执行状态。
Description: 基于任务 27 的统一调度入口提供手动刷新接口，快速返回已接受、正在执行或目标不可用的结果，不等待全部远端扫描结束才响应。通过现有查询暴露各主机的刷新进度和成功时间，前端可据此区分刷新请求已接收与数据已更新。使用可控慢主机验证连续点击不会产生重叠扫描，健康主机完成后可以立即读取新结果。

## 34. 搭建 React/Vite 页面外壳与 API 客户端
Goal: 在采集可行性通过后建立可运行的前端基础。
Description: 以前置任务 15 通过和任务 30 的接口契约为条件，在 `apps/web` 建立 React、Vite、TypeScript 页面外壳和共享契约驱动的 API 客户端。实现看板与主机设置入口、统一加载/错误/空状态以及基本键盘焦点行为，不在本任务开发会话卡片或引入新的产品功能。验收要求前端构建、类型检查通过，并能通过后端真实接口或契约一致的本地模拟响应显示连接状态。

## 35. 实现可折叠项目列表与状态计数
Goal: 按项目展示活动及需要关注的会话数量。
Description: 基于任务 34 的页面外壳和任务 30 的项目接口，实现按后端顺序显示的可折叠项目行，展示项目名称、最近 Agent 活动和 Waiting/Unread/Running 计数。让 Unknown 数量可发现，并将离线或过期计数与当前计数明确区分，刷新时保留仍存在项目的展开状态。使用包含空项目、多个项目和离线来源的固定响应进行浏览器验收，确认折叠操作和键盘展开可用。

## 36. 实现会话卡片与 Unknown 展示位置
Goal: 让用户准确识别每个原生会话的最新任务和状态可信度。
Description: 基于任务 35 的展开区域和任务 30 的会话字段实现卡片，展示任务摘要、来源工具、主机、最后活动及可用的分支/worktree。保持 Waiting → Unread → Running → Read 的相对顺序，将 Unknown 放在清晰可见的独立分组并记录这一 UI 决策，明确显示不确定原因和离线时的最后已知状态。使用五种状态、过期 Running、长文本和缺失字段进行浏览器验收，确保不会把缓存状态呈现为当前执行。

## 37. 实现最新任务详情与打开即已读
Goal: 展示最新任务内容并可靠同步已读状态。
Description: 基于任务 30 的详情接口和任务 31 的已读接口实现轻量详情视图，展示最新用户指令、最终响应、时长、时间、来源、主机、目录和可用 Git 信息。打开已完成任务时按当前任务标识确认已读并更新列表，对新任务竞态或请求失败展示真实状态；消息按不可信文本安全展示，不执行原始 HTML。验收覆盖缺失最终响应、未知时长、超长内容、运行中任务、打开期间发生新任务和重启后已读仍保留。

## 38. 实现 SSH 主机设置页面
Goal: 让用户从 Web UI 完成远端监控目标配置。
Description: 基于任务 34 的页面外壳和任务 32 的接口，展示导入的 SSH 候选、已选择目标、本机自动监控状态及最近扫描错误。实现添加、移除和启停操作，提供配置为空或认证失败时的可操作说明，不要求用户上传密钥或在远端安装采集器。通过浏览器验收验证刷新页面后设置保留、重复目标被阻止，以及一个主机失败不影响其他目标配置。

## 39. 接入前端自动更新与手动刷新
Goal: 在保持浏览器交互状态的同时展示后台采集更新。
Description: 基于任务 30/33 的接口和任务 35–38 的页面，每 15 秒获取缓存快照并接入手动刷新按钮，避免每次页面读取都触发远端采集。显示最近成功时间、刷新进行中和失败结果，防止旧响应覆盖新响应，并在项目或会话消失时合理处理展开区域与详情视图。验证多标签页不会增加后端采集频率、后台关闭时提示可见，以及离线恢复后页面能显示最新数据。

## 40. 集成本地静态服务与访问边界
Goal: 用一个本地服务同时提供构建后的前端和 API。
Description: 基于任务 34 的 Vite 构建产物和已有 Fastify API 配置静态资源服务，默认仅绑定回环地址，并让生产启动无需另起前端开发服务器。为会修改应用配置、已读状态或触发扫描的接口校验可信来源，校验 Host 并避免开放任意 CORS，日志不记录完整提示词、响应或认证材料。验证外部 Origin/Host 被拒绝、合法本地访问正常、深链接刷新可用，并检查采集代码不会写入 Agent 原始数据。

## 41. 验证完整任务生命周期与持久化
Goal: 用端到端场景证明会话、已读和隐藏规则协同正确。
Description: 基于任务 26–40 的完整应用，使用脱敏回放源、临时 SQLite 和可控时间建立 Playwright 场景，验证历史导入、Running、Waiting、明确完成、打开变 Read 和同一会话开始新任务。覆盖服务重启、完成超过 24 小时隐藏 Read、Unread 在项目有效期内保留，以及项目超过滚动 7 天后隐藏。断言每个原生会话始终只有一张卡片，查看行为不会改变项目活动时间，失败时保留可诊断的测试产物。

## 42. 验证多主机失败隔离与恢复
Goal: 证明远端故障不会阻塞健康来源或制造错误任务结论。
Description: 基于任务 27/28 的调度和新鲜度逻辑构建可控的多主机集成场景，覆盖慢连接、认证失败、断线、来源读取失败、扫描超时和恢复。验证健康主机独立更新、每目标不重叠、缓存仍可查看、过期 Running 不算当前运行，并确认无完成证据时不会自动生成 Unread。补充可访问真实 SSH 主机的只读冒烟验证，记录环境与耗时，缺少环境时明确区分模拟通过与真实验证未执行。

## 43. 完成本地安装、启动与限制说明
Goal: 让新用户可以按文档启动服务并配置已有 SSH 主机。
Description: 基于任务 40 的单服务运行方式完善安装、构建、启动和正常关闭命令，记录已验证的 Node 版本、better-sqlite3 安装条件、OpenSSH/Git 依赖及应用数据目录。说明 SSH 配置复用、首次导入语义、只读边界、支持平台与来源版本、Unknown/Web-only 限制，以及不要求远端安装新软件的前提。按干净环境步骤完成一次安装和启动检查，验证本机自动发现与主机选择流程，并记录未验证平台而不承诺支持。

## 44. 对照 MVP 验收标准完成交付检查
Goal: 为计划中的每项验收标准提供可追踪的证据或明确限制。
